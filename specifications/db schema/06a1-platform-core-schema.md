## Overview

The `kloudshop_platform` schema is the KloudShop control plane. It is a single
PostgreSQL schema within the shared GCP Cloud SQL instance (one per environment:
dev, staging, prod). Every table in this schema is shared across all merchant
tenants — no merchant ever has direct access to this schema. All reads and writes
are performed exclusively by FastAPI services running with Workload Identity
service account credentials.

This artifact covers the **core operational tables** of the platform schema:
tenant registry, staff identity, billing, trial monitoring, and platform
administration. Feature catalogue and carrier catalogue tables live in `06a2`.

**AI agent note:** All foreign keys within this schema use `UUID` primary keys
generated by PostgreSQL (`gen_random_uuid()`). Never generate UUIDs in
application code — always let the database generate them. All timestamps are
`TIMESTAMPTZ` (timezone-aware). Never use `TIMESTAMP WITHOUT TIME ZONE`.
The application layer always works in UTC; display conversion happens client-side.

## Table: `order_sources`

```sql
-- ============================================================
-- TABLE: order_sources
-- SCHEMA: kloudshop_platform
-- PURPOSE: Lookup table for all order source identifiers.
--   Replaces a fixed ENUM so new sales channels (new social
--   platforms, new POS configurations, future channels) can be
--   added with a single INSERT and zero code changes.
--   Referenced by tenant_{tenant_id}.orders.order_source_id.
--
-- BUSINESS RULES:
--   1. Only KloudShop Platform Admins may INSERT or UPDATE rows.
--      Application code reads only — never writes.
--   2. Rows are never deleted — soft-deprecate via is_active = FALSE.
--   3. 'kloudshop' and 'imported' are system-reserved codes that
--      must always exist. Do not deactivate them.
--   4. POS-location-specific sources (e.g. 'pos_nyc_store') can be
--      added at any time without schema changes.
--   5. The 'imported' source marks historical orders migrated from
--      competitor platforms — excluded from all financial reporting
--      and Stripe billing reconciliation.
-- ============================================================

CREATE TABLE kloudshop_platform.order_sources (
    source_id    VARCHAR(64) PRIMARY KEY,
    -- Human-readable identifier used in API responses and analytics.
    -- Examples: 'kloudshop', 'pos', 'imported', 'tiktok_shop',
    --           'instagram_shop', 'facebook_shop', 'pos_nyc_store'.
    -- Convention: lowercase, underscores, no spaces.

    display_name VARCHAR(128) NOT NULL,
    -- Human-readable label shown in merchant admin and analytics dashboards.
    -- Examples: 'KloudShop Storefront', 'Point of Sale', 'Imported (Historical)'.

    channel_type VARCHAR(32) NOT NULL,
    -- Broad category for analytics grouping and reporting filters.
    -- ENUM-like values (enforced by CHECK constraint below):
    --   'online'   — DTC storefront orders
    --   'pos'      — in-store POS orders
    --   'social'   — social commerce channel orders
    --   'b2b'      — B2B buyer portal orders
    --   'imported' — historical imported orders (excluded from live financials)
    --   'system'   — system-generated orders (subscriptions, etc.)

    is_active    BOOLEAN NOT NULL DEFAULT TRUE,
    -- FALSE = deprecated source. Still queryable for historical data.
    -- New orders cannot be created with an inactive source_id.

    created_at   TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at   TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    CONSTRAINT order_sources_channel_type_check CHECK (
        channel_type IN ('online', 'pos', 'social', 'b2b', 'imported', 'system')
    )
);

COMMENT ON TABLE kloudshop_platform.order_sources IS
    'Extensible lookup table for order source identifiers. Add new channels '
    'with INSERT only — no code or schema changes required.';

-- Seed data — always present
INSERT INTO kloudshop_platform.order_sources
    (source_id, display_name, channel_type) VALUES
    ('kloudshop',       'KloudShop Storefront',      'online'),
    ('pos',             'Point of Sale',              'pos'),
    ('imported',        'Imported (Historical)',       'imported'),
    ('tiktok_shop',     'TikTok Shop',                'social'),
    ('instagram_shop',  'Instagram Shopping',         'social'),
    ('facebook_shop',   'Facebook Shops',             'social'),
    ('subscription',    'Subscription (Recurring)',   'system');

-- Index: lookup by channel_type for analytics filtering
CREATE INDEX idx_order_sources_channel_type
    ON kloudshop_platform.order_sources (channel_type)
    WHERE is_active = TRUE;
-- Rationale: Analytics dashboards frequently filter orders by channel_type
-- (e.g. 'show me all social commerce revenue'). Partial index on active
-- sources only keeps it small and fast.
```

## Table: `tenants`

```sql
-- ============================================================
-- TABLE: tenants
-- SCHEMA: kloudshop_platform
-- PURPOSE: Master record for every KloudShop merchant account.
--   One row per merchant. Created during signup. Never hard-deleted.
--   Soft-deleted after trial expiry + 216-hour grace window.
--
-- BUSINESS RULES:
--   1. tenant_id is the universal foreign key used in ALL tenant-
--      scoped schema names: tenant_{tenant_id}.
--   2. slug must be globally unique — it forms the subdomain:
--      {slug}.kloudshop.biz. Validated at application layer before
--      INSERT. Never reuse a slug even after soft-deletion.
--   3. Tier transitions: DTC → Hybrid or B2B → Hybrid require explicit
--      merchant consent (US-017). Never upgrade tier in application
--      code without consent_recorded_at being set first.
--   4. Trial hard-stop has three independent triggers (DEC-12):
--      (a) trial_gcp_credit_used >= 5.00
--      (b) trial_gmv_total >= 600.00
--      (c) NOW() >= trial_start_at + INTERVAL '30 days'
--      When any trigger fires: resources suspended, published_closing_at
--      set to (trigger_time + 168 hrs rounded to next 00:00 GMT),
--      permanent_deletion_at = published_closing_at + 48 hrs.
--   5. Account is NEVER hard-deleted. soft_deleted_at marks the account
--      as deleted. Firebase Auth account IS deleted. GCIP tenant IS
--      deleted. Platform row remains forever for re-engagement detection.
--   6. is_paid transitions to TRUE when first Stripe subscription
--      payment succeeds. Resets to FALSE on suspension (not on
--      trial expiry — trial accounts were never paid).
-- ============================================================

CREATE TABLE kloudshop_platform.tenants (
    tenant_id        UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    -- Used as the PostgreSQL schema name suffix: tenant_{tenant_id}.
    -- Also used as the GCP resource label value for billing attribution.

    -- ── Identity ─────────────────────────────────────────────
    slug             VARCHAR(63) NOT NULL UNIQUE,
    -- URL-safe subdomain slug. Merchant-chosen at signup.
    -- Validated: lowercase, alphanumeric + hyphens, 3–63 chars.
    -- Forms: {slug}.kloudshop.biz (DTC) and wholesale.{slug}.kloudshop.biz (B2B).
    -- Never reused after deletion — retained as a reserved slug.

    display_name     TEXT NOT NULL,
    -- Merchant's store display name. Not unique. Used in admin UI only.

    owner_gmail      TEXT NOT NULL,
    -- Gmail address of the account owner. Matches staff_users.gmail.
    -- Denormalised here for fast lookup during auth validation.
    -- Must stay in sync with staff_role_assignments where is_owner = TRUE.

    -- ── Subscription Tier ────────────────────────────────────
    tier             VARCHAR(8) NOT NULL DEFAULT 'DTC',
    -- Current subscription tier.
    -- ENUM-like values (enforced by CHECK):
    --   'DTC'    — DTC-only storefront ($24.99/mo)
    --   'B2B'    — B2B buyer portal only ($39.99/mo)
    --   'Hybrid' — DTC + B2B simultaneously ($49.99/mo)
    -- Hybrid is paid-only — never available during trial.

    is_paid          BOOLEAN NOT NULL DEFAULT FALSE,
    -- TRUE when an active, paid Stripe subscription exists.
    -- FALSE during trial, after suspension, or after expiry.

    stripe_customer_id      TEXT,
    -- Stripe Customer ID on the KloudShop platform Stripe account.
    -- NULL until the merchant adds a payment method.

    stripe_subscription_id  TEXT,
    -- Active Stripe Subscription ID. NULL on trial or suspended accounts.

    -- ── Trial State ──────────────────────────────────────────
    is_trial                BOOLEAN NOT NULL DEFAULT TRUE,
    -- FALSE once is_paid = TRUE. Never set back to TRUE.

    trial_tier              VARCHAR(8),
    -- The tier the merchant chose at signup for their trial.
    -- ENUM: 'DTC' | 'B2B'. Hybrid is never a trial tier.

    trial_start_at          TIMESTAMPTZ,
    -- Set at account creation. Used to calculate day-30 hard-stop.

    trial_gcp_credit_used   DECIMAL(10, 4) NOT NULL DEFAULT 0,
    -- Cumulative GCP spend against the $5.00 trial credit cap.
    -- Updated by the billing reconciliation Cloud Tasks job.
    -- Hard-stop fires when this reaches 5.0000.

    trial_gmv_total         DECIMAL(12, 2) NOT NULL DEFAULT 0,
    -- Cumulative pre-tax GMV against the $600.00 trial GMV cap.
    -- Updated by the order placement flow on each confirmed order.
    -- Hard-stop fires when this reaches 600.00.

    trial_hard_stop_trigger VARCHAR(16),
    -- Which trigger fired the hard-stop. NULL if not yet stopped.
    -- Values: 'gcp_credit' | 'gmv_cap' | 'day_30'

    trial_hard_stop_at      TIMESTAMPTZ,
    -- Timestamp when the hard-stop trigger fired.

    trial_published_closing_at TIMESTAMPTZ,
    -- Shown to merchant in admin: "Your store closes on {date} at 00:00 GMT".
    -- = trial_hard_stop_at + 168 hours, rounded up to next 00:00 GMT.

    trial_permanent_deletion_at TIMESTAMPTZ,
    -- When permanent data deletion executes.
    -- = trial_published_closing_at + 48 hours (silent grace period).
    -- Total window from hard-stop: 216 hours.

    -- ── Account Lifecycle ────────────────────────────────────
    account_status   VARCHAR(16) NOT NULL DEFAULT 'provisioning',
    -- Current operational state of the account.
    -- Values:
    --   'provisioning'  — GCP resources being created (SYS-01 in progress)
    --   'active'        — fully operational (trial or paid)
    --   'hard_stopped'  — trial hard-stop fired; resources suspended
    --   'suspended'     — payment failed; admin access restricted to billing
    --   'deleted'       — 216-hour window elapsed; data permanently deleted
    -- Note: 'deleted' accounts retain this row. All tenant data is gone
    -- but this platform record remains for deduplication and re-engagement.

    soft_deleted_at  TIMESTAMPTZ,
    -- Set when account_status transitions to 'deleted'.
    -- Never hard-delete this row.

    -- ── Infrastructure ───────────────────────────────────────
    gcip_tenant_id   TEXT,
    -- Firebase/GCIP tenant ID for consumer auth on this storefront.
    -- Set during GCP provisioning (SYS-01). NULL until provisioned.
    -- See also: gcip_tenant_registry table.

    gcp_provisioning_status VARCHAR(16) NOT NULL DEFAULT 'pending',
    -- Tracks GCP resource provisioning state during signup (SYS-01).
    -- Values: 'pending' | 'in_progress' | 'complete' | 'failed'

    primary_region   VARCHAR(32),
    -- GCP region for primary infrastructure.
    -- Examples: 'us-central1', 'europe-west2', 'australia-southeast1'

    custom_domain_dtc  TEXT,
    -- Merchant's custom domain for DTC storefront (e.g. 'www.acmeco.com').
    -- NULL if using default kloudshop.biz subdomain.

    custom_domain_b2b  TEXT,
    -- Merchant's custom domain for B2B portal (e.g. 'wholesale.acmeco.com').
    -- NULL if using default wholesale.{slug}.kloudshop.biz subdomain.

    -- ── Metadata ─────────────────────────────────────────────
    created_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    CONSTRAINT tenants_tier_check CHECK (
        tier IN ('DTC', 'B2B', 'Hybrid')
    ),
    CONSTRAINT tenants_trial_tier_check CHECK (
        trial_tier IN ('DTC', 'B2B') OR trial_tier IS NULL
    ),
    CONSTRAINT tenants_account_status_check CHECK (
        account_status IN (
            'provisioning', 'active', 'hard_stopped',
            'suspended', 'deleted'
        )
    ),
    CONSTRAINT tenants_gcp_status_check CHECK (
        gcp_provisioning_status IN ('pending', 'in_progress', 'complete', 'failed')
    ),
    CONSTRAINT tenants_hard_stop_trigger_check CHECK (
        trial_hard_stop_trigger IN ('gcp_credit', 'gmv_cap', 'day_30')
        OR trial_hard_stop_trigger IS NULL
    )
);

COMMENT ON TABLE kloudshop_platform.tenants IS
    'Master merchant account registry. One row per merchant. Never hard-deleted. '
    'Soft-deleted accounts retain their row indefinitely for deduplication.';

-- Indexes
CREATE UNIQUE INDEX idx_tenants_slug
    ON kloudshop_platform.tenants (slug);
-- Rationale: Subdomain routing resolves tenant_id from slug on every
-- storefront request. Must be unique and fast. Unique constraint also
-- enforced at application layer to give a better error message than
-- a DB constraint violation.

CREATE INDEX idx_tenants_account_status
    ON kloudshop_platform.tenants (account_status)
    WHERE soft_deleted_at IS NULL;
-- Rationale: Platform Admin dashboard filters merchants by status.
-- Partial index excludes deleted accounts (the majority over time).

CREATE INDEX idx_tenants_owner_gmail
    ON kloudshop_platform.tenants (owner_gmail);
-- Rationale: Auth middleware looks up tenant by owner Gmail on login
-- to populate the admin dashboard. Not unique — an owner can transfer
-- and be re-invited, so historical records may share a Gmail.

CREATE INDEX idx_tenants_is_trial_active
    ON kloudshop_platform.tenants (is_trial, account_status)
    WHERE is_trial = TRUE AND soft_deleted_at IS NULL;
-- Rationale: Trial monitoring jobs (GMV cap, GCP credit check, day-30)
-- run only on active trial accounts. This partial index makes those
-- Cloud Tasks jobs fast even with thousands of tenants.

CREATE INDEX idx_tenants_stripe_customer
    ON kloudshop_platform.tenants (stripe_customer_id)
    WHERE stripe_customer_id IS NOT NULL;
-- Rationale: Stripe webhook handler looks up tenant by stripe_customer_id
-- on every billing event (payment succeeded, failed, subscription updated).
```

## Table: `tenant_regions`

```sql
-- ============================================================
-- TABLE: tenant_regions
-- SCHEMA: kloudshop_platform
-- PURPOSE: GCP region assignments per tenant. A tenant with only
--   a primary region has one row. A tenant who activates a secondary
--   region gets a second row. Provisioning status is tracked per row.
--
-- BUSINESS RULES:
--   1. Every tenant has exactly one row with is_primary = TRUE.
--   2. A tenant may have zero or one rows with is_primary = FALSE
--      (the secondary region). Multiple secondary regions are not
--      supported at MVP.
--   3. Secondary region activation requires 48-hour lead time warning
--      (enforced in application layer, not DB).
--   4. Deactivating a secondary region sets is_active = FALSE and
--      deprovisioned_at = NOW(). The row is retained for audit.
--   5. provisioning_status transitions: pending → in_progress →
--      active → deprovisioning → deprovisioned.
-- ============================================================

CREATE TABLE kloudshop_platform.tenant_regions (
    region_id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    tenant_id           UUID NOT NULL
                        REFERENCES kloudshop_platform.tenants (tenant_id)
                        ON DELETE RESTRICT,
    -- RESTRICT: never cascade-delete region records if a tenant row
    -- is somehow deleted. This should never happen (tenants are soft-deleted)
    -- but RESTRICT is the safe default.

    gcp_region          VARCHAR(32) NOT NULL,
    -- GCP region identifier. Examples: 'us-central1', 'europe-west2'.

    is_primary          BOOLEAN NOT NULL DEFAULT TRUE,
    -- TRUE for the merchant's chosen primary region (always present).
    -- FALSE for the optional secondary failover region.

    is_active           BOOLEAN NOT NULL DEFAULT FALSE,
    -- TRUE when GCP resources in this region are fully provisioned and
    -- receiving traffic. FALSE during provisioning or after deprovisioning.

    provisioning_status VARCHAR(16) NOT NULL DEFAULT 'pending',
    -- Current provisioning state for resources in this region.
    -- Values: 'pending' | 'in_progress' | 'active' | 'deprovisioning'
    --         | 'deprovisioned' | 'failed'

    provisioned_at      TIMESTAMPTZ,
    -- When provisioning_status first reached 'active'.

    deprovisioned_at    TIMESTAMPTZ,
    -- When deprovisioning completed. NULL if still active.

    created_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at          TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    CONSTRAINT tenant_regions_provisioning_status_check CHECK (
        provisioning_status IN (
            'pending', 'in_progress', 'active',
            'deprovisioning', 'deprovisioned', 'failed'
        )
    ),
    -- Enforce at most one primary region per tenant
    CONSTRAINT tenant_regions_one_primary_per_tenant UNIQUE (tenant_id, is_primary)
    -- Note: This unique constraint prevents two rows with is_primary = TRUE
    -- for the same tenant. It does NOT prevent two rows with is_primary = FALSE
    -- (though application logic prevents this at MVP).
);

COMMENT ON TABLE kloudshop_platform.tenant_regions IS
    'GCP region assignments per tenant. Primary region always present. '
    'Secondary region optional — activated on-demand before peak events.';

CREATE INDEX idx_tenant_regions_tenant_id
    ON kloudshop_platform.tenant_regions (tenant_id);
-- Rationale: Provisioning service and billing service look up all regions
-- for a tenant frequently. Single-column index sufficient given low
-- cardinality per tenant (max 2 rows).

CREATE INDEX idx_tenant_regions_active
    ON kloudshop_platform.tenant_regions (gcp_region, is_active)
    WHERE is_active = TRUE;
-- Rationale: Load balancer routing and health check jobs query which
-- regions are active per GCP region for cross-region traffic management.
```

## Table: `gcip_tenant_registry`

```sql
-- ============================================================
-- TABLE: gcip_tenant_registry
-- SCHEMA: kloudshop_platform
-- PURPOSE: Maps KloudShop tenant_id → GCIP (Google Cloud Identity
--   Platform) tenant_id string. Required because GCIP generates its
--   own tenant ID strings (not UUIDs) when a tenant is provisioned
--   programmatically via the Firebase Admin SDK.
--
-- BUSINESS RULES:
--   1. One row per KloudShop tenant. Created during SYS-01 provisioning.
--   2. gcip_tenant_id is a Firebase-generated string (e.g. 'kloudshop-
--      acmeco-xyz123'). Never manually set — always from Firebase Admin SDK.
--   3. This table is the authoritative source for which GCIP tenant
--      serves consumer auth for a given KloudShop storefront.
--   4. When a tenant is soft-deleted, the GCIP tenant is hard-deleted
--      via Firebase Admin SDK. This row is then marked gcip_deleted = TRUE.
--      The row itself is never deleted (audit trail).
--   5. Consumer JWTs carry the GCIP tenant_id claim. FastAPI resolves
--      the KloudShop tenant_id by querying this table (cached in Redis).
-- ============================================================

CREATE TABLE kloudshop_platform.gcip_tenant_registry (
    registry_id      UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    tenant_id        UUID NOT NULL UNIQUE
                     REFERENCES kloudshop_platform.tenants (tenant_id)
                     ON DELETE RESTRICT,
    -- One GCIP tenant per KloudShop tenant. UNIQUE enforces this.

    gcip_tenant_id   TEXT NOT NULL UNIQUE,
    -- Firebase/GCIP-generated tenant identifier string.
    -- Example: 'kloudshop-acmeco-a1b2c3'
    -- Set by the GCP provisioning job via Firebase Admin SDK:
    --   tenant = firebase_admin.auth.tenant_mgt.create_tenant(...)
    --   gcip_tenant_id = tenant.tenant_id

    gcip_deleted     BOOLEAN NOT NULL DEFAULT FALSE,
    -- TRUE when the GCIP tenant has been hard-deleted from Firebase
    -- (occurs when the KloudShop tenant is soft-deleted after trial expiry).
    -- The row is retained here for audit purposes.

    provisioned_at   TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    -- When the GCIP tenant was successfully created.

    deleted_at       TIMESTAMPTZ,
    -- When the GCIP tenant was deleted from Firebase. NULL if still active.

    created_at       TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

COMMENT ON TABLE kloudshop_platform.gcip_tenant_registry IS
    'Maps KloudShop tenant_id to Firebase GCIP tenant_id. Used by FastAPI '
    'to resolve consumer JWT claims to the correct KloudShop tenant. '
    'Cached in Redis (TTL: 1 hour) to avoid per-request DB reads.';

CREATE UNIQUE INDEX idx_gcip_registry_tenant_id
    ON kloudshop_platform.gcip_tenant_registry (tenant_id);
-- Rationale: Primary lookup path — resolve KloudShop tenant_id from
-- a consumer's GCIP tenant_id claim. Must be unique and O(1).

CREATE UNIQUE INDEX idx_gcip_registry_gcip_tenant_id
    ON kloudshop_platform.gcip_tenant_registry (gcip_tenant_id)
    WHERE gcip_deleted = FALSE;
-- Rationale: Reverse lookup — given a GCIP tenant_id from a JWT claim,
-- find the KloudShop tenant_id. Partial index excludes deleted tenants.
```

## Table: `staff_users`

```sql
-- ============================================================
-- TABLE: staff_users
-- SCHEMA: kloudshop_platform
-- PURPOSE: Platform-level identity records for all merchant staff.
--   One row per Gmail account, regardless of how many tenancies
--   that person belongs to. Multi-tenancy membership is in
--   staff_role_assignments, not here.
--
-- BUSINESS RULES:
--   1. Only Gmail accounts are supported for merchant staff (DEC-13).
--      No username/password auth for staff. Google handles credential
--      security and MFA.
--   2. One staff_users row per Gmail address globally. If a person
--      is invited to multiple merchant stores, they get one row here
--      and multiple rows in staff_role_assignments.
--   3. preferences JSONB stores UI settings (DEC-23, DMF-10).
--      Currently supported keys:
--        "theme_mode": "light" | "dark" | "system" (default: "system")
--      Future keys added without schema migration.
--   4. firebase_uid links to the Firebase Auth UID for this Gmail.
--      Set on first login (Google OAuth callback). NULL until first login.
--   5. last_login_at is updated on every successful JWT validation —
--      do not update it more than once per minute (application layer
--      rate-limit to avoid write amplification).
-- ============================================================

CREATE TABLE kloudshop_platform.staff_users (
    staff_user_id    UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    gmail            TEXT NOT NULL UNIQUE,
    -- Gmail address. Normalised to lowercase before storage.
    -- Used as the lookup key during Google OAuth callback.

    firebase_uid     TEXT UNIQUE,
    -- Firebase Auth UID for this Gmail account.
    -- Set on first successful Google OAuth login. NULL before first login.
    -- Used by FastAPI to validate JWT sub claim.

    display_name     TEXT,
    -- Full name as returned by Google OAuth (given_name + family_name).
    -- Updated on every login to stay in sync with Google profile.

    avatar_url       TEXT,
    -- Google profile picture URL. Updated on every login.
    -- May be NULL if Google does not provide one.

    preferences      JSONB NOT NULL DEFAULT '{}',
    -- User UI preferences (DMF-10, DEC-23).
    -- Schema: { "theme_mode": "system" | "light" | "dark" }
    -- Fetched on session bootstrap; updated via PATCH /me/preferences.
    -- Never stored in Firebase Auth custom claims (reserved for RBAC).
    -- Extensible: future preference keys added without schema migration.

    is_active        BOOLEAN NOT NULL DEFAULT TRUE,
    -- FALSE when all staff_role_assignments for this user are revoked.
    -- Does not delete the row — preserves audit trail.

    last_login_at    TIMESTAMPTZ,
    -- Updated on successful authentication. NULL until first login.

    created_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at       TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

COMMENT ON TABLE kloudshop_platform.staff_users IS
    'Platform-level merchant staff identities. One row per Gmail account. '
    'Multi-tenancy membership tracked in staff_role_assignments. '
    'UI preferences stored in preferences JSONB — never in Firebase claims.';

CREATE UNIQUE INDEX idx_staff_users_gmail
    ON kloudshop_platform.staff_users (gmail);
-- Rationale: Primary lookup during Google OAuth callback — resolve
-- Gmail to staff_user_id. Must be unique and O(1).

CREATE UNIQUE INDEX idx_staff_users_firebase_uid
    ON kloudshop_platform.staff_users (firebase_uid)
    WHERE firebase_uid IS NOT NULL;
-- Rationale: JWT validation extracts firebase_uid from sub claim.
-- FastAPI looks up staff_user_id from firebase_uid on every request.
-- Partial index excludes NULL values (users who have never logged in).

CREATE INDEX idx_staff_users_is_active
    ON kloudshop_platform.staff_users (is_active)
    WHERE is_active = TRUE;
-- Rationale: Admin user management screens filter to active users only.
```

## Table: `staff_role_assignments`

```sql
-- ============================================================
-- TABLE: staff_role_assignments
-- SCHEMA: kloudshop_platform
-- PURPOSE: Maps staff members to tenancies with specific roles.
--   A staff member can belong to multiple tenancies (e.g. an agency
--   managing multiple merchant stores). A staff member can hold
--   multiple roles within a single tenancy.
--
-- BUSINESS RULES:
--   1. One row per (staff_user_id, tenant_id, role) combination.
--      Multiple roles = multiple rows for the same (staff, tenant).
--   2. is_owner = TRUE marks the account Owner. Exactly one staff
--      member per tenant must have is_owner = TRUE at all times.
--      Enforced by a partial unique index below.
--   3. Invitation flow: row created with status = 'pending'.
--      On acceptance: status = 'active', accepted_at = NOW().
--   4. Revocation: status = 'revoked', revoked_at = NOW().
--      Row is retained — never deleted (audit trail).
--   5. Valid roles (enforced by CHECK constraint):
--      'owner', 'admin', 'store_manager', 'fulfilment_staff',
--      'inventory_manager', 'marketing_manager', 'customer_support',
--      'analyst_finance', 'catalogue_manager', 'b2b_account_manager',
--      'b2b_sales_rep', 'pos_operator', 'developer_integrator'
--   6. Firebase custom claims are built from active rows for the
--      current tenant: roles[] array + is_owner boolean.
--      Claims are refreshed on every login and on role change.
-- ============================================================

CREATE TABLE kloudshop_platform.staff_role_assignments (
    assignment_id    UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    staff_user_id    UUID NOT NULL
                     REFERENCES kloudshop_platform.staff_users (staff_user_id)
                     ON DELETE RESTRICT,
    -- RESTRICT: never auto-delete assignments if a staff_users row
    -- were somehow deleted. Staff rows are never deleted anyway.

    tenant_id        UUID NOT NULL
                     REFERENCES kloudshop_platform.tenants (tenant_id)
                     ON DELETE RESTRICT,
    -- RESTRICT: never auto-delete assignments on tenant deletion.
    -- Tenant rows are soft-deleted; assignments must be explicitly revoked.

    role             VARCHAR(32) NOT NULL,
    -- The specific role granted. See business rules for valid values.

    is_owner         BOOLEAN NOT NULL DEFAULT FALSE,
    -- TRUE for the account owner. Used to build the is_owner custom claim.
    -- Only meaningful when role = 'owner'.

    status           VARCHAR(16) NOT NULL DEFAULT 'pending',
    -- Invitation/assignment lifecycle state.
    -- Values: 'pending' | 'active' | 'revoked'

    invited_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    -- When the invitation email was sent.

    accepted_at      TIMESTAMPTZ,
    -- When the invitee accepted via the invitation link. NULL if pending.

    revoked_at       TIMESTAMPTZ,
    -- When access was revoked. NULL if not revoked.

    revoked_by       UUID
                     REFERENCES kloudshop_platform.staff_users (staff_user_id)
                     ON DELETE SET NULL,
    -- staff_user_id of the person who revoked access. NULL if not revoked.
    -- SET NULL on delete: if the revoker's account is somehow removed,
    -- we lose the reference but retain the revocation fact.

    created_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    CONSTRAINT staff_role_assignments_role_check CHECK (
        role IN (
            'owner', 'admin', 'store_manager', 'fulfilment_staff',
            'inventory_manager', 'marketing_manager', 'customer_support',
            'analyst_finance', 'catalogue_manager', 'b2b_account_manager',
            'b2b_sales_rep', 'pos_operator', 'developer_integrator'
        )
    ),
    CONSTRAINT staff_role_assignments_status_check CHECK (
        status IN ('pending', 'active', 'revoked')
    ),
    -- Prevent duplicate active role assignments
    CONSTRAINT staff_role_assignments_unique_active
        UNIQUE (staff_user_id, tenant_id, role, status)
);

COMMENT ON TABLE kloudshop_platform.staff_role_assignments IS
    'Maps staff members to tenancies with specific roles. Multiple roles '
    'per (staff, tenant) pair are supported via multiple rows. '
    'Revoked assignments are retained for audit trail.';

-- Enforce exactly one owner per tenant (partial unique index)

    ON kloudshop_platform.staff_role_assignments (tenant_id)
    WHERE is_owner = TRUE AND status = 'active';
-- Rationale: Exactly one active owner per tenant at all times.
```

```sql
-- ============================================================
-- TABLE: migration_jobs
-- SCHEMA: kloudshop_platform
-- PURPOSE: Tracks competitor store scraping and import jobs per
--   tenant. One row per migration attempt. A tenant may have
--   multiple rows if they retry or run the CSV fallback after
--   a failed scrape.
--
-- BUSINESS RULES:
--   1. Created when a merchant submits a competitor URL or CSV.
--   2. scrape_status and import_status are independent — a job
--      can have scraping complete but import still in progress.
--   3. 'blocked' scrape_status means the competitor platform
--      returned bot-protection responses. The CSV fallback flow
--      (US-013) is automatically offered to the merchant.
--   4. gcp_track_b_status tracks GCP infrastructure provisioning
--      (SYS-01 Track B) which runs in parallel with scraping.
--      The "store is ready" message only shows when BOTH
--      scrape/import AND gcp_track_b_status are 'complete'.
--   5. retry_count is incremented by Cloud Tasks on each retry.
--      Max retries: 5 (configured in Cloud Tasks queue settings).
--   6. products_imported, seo_pages_imported are denormalised
--      counts for the progress narrative UI — not authoritative
--      inventory counts (those live in the tenant schema).
-- ============================================================

CREATE TABLE kloudshop_platform.migration_jobs (
    job_id               UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    tenant_id            UUID NOT NULL
                         REFERENCES kloudshop_platform.tenants (tenant_id)
                         ON DELETE RESTRICT,

    job_type             VARCHAR(16) NOT NULL DEFAULT 'scrape',
    -- 'scrape' — automated competitor URL scraping (US-011)
    -- 'csv'    — manual CSV product catalog upload (US-013)
    -- 'customer_csv' — manual customer + order CSV upload (US-014)

    source_platform      VARCHAR(32),
    -- Detected source platform. NULL for CSV jobs.
    -- Values: 'shopify' | 'woocommerce' | 'adobe_commerce'
    --         | 'wix' | 'squarespace' | 'unknown'

    -- 'partial' = some rows failed validation but others succeeded.

    gcp_track_b_status   VARCHAR(16) NOT NULL DEFAULT 'pending',

    -- Used by the progress narrative UI: "Importing {N} products..."

    seo_pages_imported   INTEGER NOT NULL DEFAULT 0,

    cloud_task_name      TEXT,
    -- GCP Cloud Tasks task name for this job. Used for cancellation
    -- and status correlation with Cloud Tasks logs.

    started_at           TIMESTAMPTZ,
    completed_at         TIMESTAMPTZ,
    created_at           TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at           TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    CONSTRAINT migration_jobs_type_check CHECK (

    CONSTRAINT migration_jobs_scrape_status_check CHECK (

    ),
    CONSTRAINT migration_jobs_import_status_check CHECK (
        import_status IN ('pending', 'in_progress', 'complete', 'failed', 'partial')
    ),
    CONSTRAINT migration_jobs_gcp_status_check CHECK (
        gcp_track_b_status IN ('pending', 'in_progress', 'complete', 'failed')
    )
);

COMMENT ON TABLE kloudshop_platform.migration_jobs IS
```

```sql
-- ============================================================
-- TABLE: billing_cycles
-- SCHEMA: kloudshop_platform
-- PURPOSE: One row per merchant per monthly billing period.
--   Created by the billing service at the start of each cycle.
--   Updated as GCP costs accrue and when the Stripe invoice is issued.
--
-- BUSINESS RULES:
--   1. cycle_start and cycle_end define the billing window.
--      Aligned to the merchant's subscription anniversary date.
--   2. gcp_actual_cost_usd = sum of all billing_line_items for
--      this cycle. Updated nightly by the billing reconciliation job.
--   3. kloudshop_markup_usd = gcp_actual_cost_usd × 0.15 (fixed 15%).
--   4. total_gcp_charged_usd = gcp_actual_cost_usd + kloudshop_markup_usd
--      = gcp_actual_cost_usd × 1.15
--   5. stripe_invoice_id is set when the Stripe invoice is issued at
--      cycle end. NULL during the active cycle.
--   6. payment_status: 'open' → 'paid' on Stripe payment success;
--      'open' → 'failed' on Stripe dunning exhaustion.
-- ============================================================

CREATE TABLE kloudshop_platform.billing_cycles (
    cycle_id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    tenant_id            UUID NOT NULL
                         REFERENCES kloudshop_platform.tenants (tenant_id)
                         ON DELETE RESTRICT,

    cycle_start          TIMESTAMPTZ NOT NULL,
    cycle_end            TIMESTAMPTZ NOT NULL,

    subscription_fee_usd DECIMAL(10, 2) NOT NULL,
    -- Flat subscription amount for this cycle.
    -- DTC: 24.99 | B2B: 39.99 | Hybrid: 49.99

    gcp_actual_cost_usd  DECIMAL(12, 4) NOT NULL DEFAULT 0,
    -- Sum of actual GCP resource costs from GCP Billing Export.
    -- Updated nightly. Final value set at cycle end before invoicing.

    kloudshop_markup_usd DECIMAL(12, 4) NOT NULL DEFAULT 0,
    -- Fixed 15% markup on gcp_actual_cost_usd.
    -- = gcp_actual_cost_usd × 0.15

    total_gcp_charged_usd DECIMAL(12, 4) NOT NULL DEFAULT 0,
    -- What the merchant pays for GCP usage: gcp_actual_cost_usd × 1.15

    stripe_invoice_id    TEXT,
    -- Stripe Invoice ID. NULL during the active cycle.
    -- Set when the invoice is generated at cycle end.

    payment_status       VARCHAR(16) NOT NULL DEFAULT 'open',
    -- Values: 'open' | 'paid' | 'failed' | 'voided'

    invoice_issued_at    TIMESTAMPTZ,
    -- When the Stripe invoice was issued. NULL during active cycle.

    paid_at              TIMESTAMPTZ,
    -- When payment was confirmed by Stripe webhook. NULL if not yet paid.

    created_at           TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at           TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    CONSTRAINT billing_cycles_payment_status_check CHECK (
        payment_status IN ('open', 'paid', 'failed', 'voided')
    ),
    CONSTRAINT billing_cycles_dates_check CHECK (
        cycle_end > cycle_start
    )
);

COMMENT ON TABLE kloudshop_platform.billing_cycles IS
    'One row per merchant per monthly billing period. GCP costs accumulated '
    'nightly. Stripe invoice issued at cycle end. merchant_bill = gcp_cost × 1.15.';

CREATE INDEX idx_billing_cycles_tenant

-- Rationale: Billing history screen shows all cycles for a tenant,
-- most recent first.

CREATE INDEX idx_billing_cycles_open
    ON kloudshop_platform.billing_cycles (payment_status, cycle_end)
    WHERE payment_status = 'open';
-- Rationale: Billing service end-of-cycle job queries for all open

CREATE INDEX idx_billing_cycles_stripe_invoice

    WHERE stripe_invoice_id IS NOT NULL;
-- Rationale: Stripe webhook handler resolves billing_cycle from
```

```sql
-- TABLE: billing_line_items

    --   'cloud_sql', 'cloud_run', 'cloud_storage', 'vertex_ai',
```

```sql
-- TABLE: trial_visitor_counts

    count_date       DATE NOT NULL,
    -- The calendar date (UTC) for which this count applies.

    visitor_count    INTEGER NOT NULL DEFAULT 0,

    -- merchant for this count. Prevents duplicate sends on job retry.

    email_sent_at    TIMESTAMPTZ,
    -- When the email was dispatched. NULL if email_sent = FALSE.

    created_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    -- Prevents duplicate rows for the same tenant on the same day.
```

```sql
-- ============================================================
-- TABLE: platform_announcements
-- SCHEMA: kloudshop_platform
-- PURPOSE: Human-authored release notes per production deployment.
--   Written by KloudShop Platform Admin after a deploy. Read by the
--   Flutter admin app to render a "What's new" panel when the
--   SYS-18 service worker detects a version change.
--
-- BUSINESS RULES:
--   1. version.json (Cloud Storage) is machine-written by CI/CD —
--      it carries only the build hash, timestamp, and features_added
--      integer. This table carries the human-readable release notes.
--   2. build_hash links this announcement to the version.json entry.

--      after the service worker signals a new version.
--   3. is_published = FALSE allows Platform Admin to draft an
--      announcement before publishing. The "What's new" panel only
--      shows published announcements.
--   4. features_added_count is denormalised from version.json for
--      convenience — used in the "X new features available" banner text.
--   5. body_markdown holds the full release notes in Markdown.
--      The Flutter admin renders it via a Markdown widget.
-- ============================================================

CREATE TABLE kloudshop_platform.platform_announcements (
    announcement_id      UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    build_hash           TEXT NOT NULL UNIQUE,
    -- Git commit SHA / build hash from version.json.
    -- Links this human-authored announcement to the machine-generated
    -- version.json on Cloud Storage.

    version_label        TEXT,
    -- Optional human-friendly version label. Examples: 'v1.1', 'v1.2-beta'.
    -- NULL if the team does not use semantic versioning labels.

    title                TEXT NOT NULL,
    -- Short announcement headline. Example: "3 new features live today".

    body_markdown        TEXT NOT NULL,
    -- Full release notes in Markdown. Rendered in the Flutter admin
    -- "What's new" panel via a Markdown rendering widget.

    features_added_count INTEGER NOT NULL DEFAULT 0,
    -- Count of new Feature Catalogue items in this release.
    -- Sourced from version.json features_added field.
    -- Used in banner: "✨ {N} new features available".

    is_published         BOOLEAN NOT NULL DEFAULT FALSE,
    -- FALSE = draft (not shown to merchants).
    -- TRUE = visible in "What's new" panel.

    published_at         TIMESTAMPTZ,
    -- When is_published was set to TRUE.

    published_by         UUID
                         REFERENCES kloudshop_platform.platform_staff (platform_staff_id)
                         ON DELETE SET NULL,
    -- Platform Admin who published this announcement.

    deployed_at          TIMESTAMPTZ NOT NULL,
    -- When the production deployment for this build_hash occurred.
    -- Sourced from version.json deployed_at field.

    created_at           TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at           TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

COMMENT ON TABLE kloudshop_platform.platform_announcements IS
    'Human-authored release notes per production deployment. '
    'Paired with machine-generated version.json on Cloud Storage. '
    'Read by Flutter admin What''s New panel after SYS-18 version detection.';

CREATE UNIQUE INDEX idx_platform_announcements_build_hash
    ON kloudshop_platform.platform_announcements (build_hash);
-- Rationale: Flutter app fetches announcement by build_hash from

CREATE INDEX idx_platform_announcements_published
    ON kloudshop_platform.platform_announcements (published_at DESC)

-- announcements. Partial index on published only.
```

## Table: `feature_request_channel`

```sql
-- ============================================================
-- TABLE: feature_request_channel
-- SCHEMA: kloudshop_platform
-- PURPOSE: Merchant-submitted feature requests for the KloudShop
--   Feature Request Channel. Only authenticated merchants on paid
--   tiers or active trials may submit. Accessible to all qualifying
--   merchants — not publicly visible.
--
-- BUSINESS RULES:
--   1. Only one active request per tenant per title (soft-dedup at
--      application layer — show "similar request exists" before creating).
--   2. vote_count is a denormalised count updated on every INSERT/DELETE
--      in feature_request_votes. Never computed on-the-fly — too slow
--      for ordered listing.
--   3. status lifecycle: 'open' → 'under_review' → 'planned' →
--      'delivered' | 'declined'.
--   4. platform_notes is visible to Platform Admins only — never
--      shown to merchants. Used for internal triage notes.
--   5. submitted_by_tenant_id is NOT shown to other merchants —
--      request submitter identity is private within the channel.
-- ============================================================

CREATE TABLE kloudshop_platform.feature_request_channel (
    request_id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),

    submitted_by_tenant_id UUID NOT NULL
                           REFERENCES kloudshop_platform.tenants (tenant_id)
                           ON DELETE RESTRICT,
    -- The merchant tenant who submitted this request.
    -- Identity is not exposed to other merchants in the UI.

    title                TEXT NOT NULL,
    -- Short feature request title. Max 200 chars enforced at application layer.

    description          TEXT,
    -- Optional detailed description of the requested feature.

    vote_count           INTEGER NOT NULL DEFAULT 1,
    -- Denormalised vote count. Starts at 1 (submitter's auto-vote).
    -- Updated by trigger or application code on feature_request_votes changes.
    -- Never computed on-the-fly.

    status               VARCHAR(16) NOT NULL DEFAULT 'open',
    -- Values: 'open' | 'under_review' | 'planned' | 'delivered' | 'declined'

    platform_notes       TEXT,
    -- Internal KloudShop triage notes. Never visible to merchants.

    delivered_in_build   TEXT,
    -- build_hash from platform_announcements when this feature shipped.
    -- NULL until status = 'delivered'.

    created_at           TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at           TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    CONSTRAINT feature_request_status_check CHECK (
        status IN ('open', 'under_review', 'planned', 'delivered', 'declined')
    )
);

COMMENT ON TABLE kloudshop_platform.feature_request_channel IS
    'Merchant-submitted feature requests. Authenticated paid/trial merchants only. '
    'vote_count denormalised for fast ordered listing. Submitter identity private.';

CREATE INDEX idx_feature_requests_by_votes
    ON kloudshop_platform.feature_request_channel (vote_count DESC, created_at DESC)
    WHERE status IN ('open', 'under_review');
-- Rationale: Default view sorts by votes descending. Partial index
-- on active statuses only — delivered and declined requests are
-- shown in a separate history view.

CREATE INDEX idx_feature_requests_by_tenant
    ON kloudshop_platform.feature_request_channel (submitted_by_tenant_id);
-- Rationale: "My requests" view shows all requests from a specific tenant.
```

## Table: `feature_request_votes`

```sql
-- ============================================================
-- TABLE: feature_request_votes
-- SCHEMA: kloudshop_platform
-- PURPOSE: Individual vote records. One row per (tenant, request).
--   Enforces one vote per merchant per feature request.
--
-- BUSINESS RULES:
--   1. One vote per (tenant_id, request_id). Enforced by PRIMARY KEY.
--   2. On INSERT: increment feature_request_channel.vote_count by 1.
--   3. On DELETE (vote retraction): decrement vote_count by 1.
--      Application layer must enforce vote_count >= 1 (submitter
--      auto-vote cannot be retracted).
--   4. Submitter auto-vote is created atomically with the request row
--      in a single transaction.
-- ============================================================

CREATE TABLE kloudshop_platform.feature_request_votes (
    tenant_id   UUID NOT NULL
                REFERENCES kloudshop_platform.tenants (tenant_id)
                ON DELETE CASCADE,
    -- CASCADE: if a tenant is deleted, their votes are removed.
    -- vote_count reconciliation after CASCADE is handled by a
    -- nightly consistency check job.

    request_id  UUID NOT NULL
                REFERENCES kloudshop_platform.feature_request_channel (request_id)
                ON DELETE CASCADE,
    -- CASCADE: if a request is deleted, its votes go with it.

    voted_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),

    PRIMARY KEY (tenant_id, request_id)
    -- Composite PK enforces one vote per (tenant, request).
);

COMMENT ON TABLE kloudshop_platform.feature_request_votes IS
    'One row per (tenant, feature_request) vote. Composite PK enforces '
    'one vote per merchant per request. vote_count on parent table '
    'is updated on every INSERT/DELETE here.';

CREATE INDEX idx_feature_votes_request
    ON kloudshop_platform.feature_request_votes (request_id, voted_at DESC);
-- Rationale: vote_count recalculation on demand requires counting
-- all votes for a given request_id.
```
